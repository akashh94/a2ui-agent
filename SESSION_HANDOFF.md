## Deployment how-to (Windows)

No bash on PATH — use **Git Bash** (`C:\Program Files\Git\bin\bash.exe`). The
scripts install/use `uv` + `agents-cli` themselves; no manual venv needed, but
`agents-cli` requires `$HOME/.local/bin` on PATH (build scripts add it; deploy
scripts do NOT — run `export PATH="$HOME/.local/bin:$PATH"` first if `agents-cli:
command not found`).

Order matters — **server first, then agent** (agent's `CATALOG_URL` is the
server URL):

```bash
# a2ui-server (Cloud Run)
cd a2ui-server && ./build.personal.sh && ./deploy.personal.sh

# a2ui-agent (Agent Engine)
export PATH="$HOME/.local/bin:$PATH"
cd a2ui-agent && ./build.personal.sh && ./deploy.personal.sh
```

## Key implementation details

### a2ui-server (`a2ui-server/server.py`)
- `/chat` calls the engine's REST `:streamQuery` directly (not the SDK client):
  `https://{location}-aiplatform.googleapis.com/v1/projects/{p}/locations/{l}/reasoningEngines/{id}:streamQuery`
  with `class_method: stream_query` and `run_config.streaming_mode: sse` (matching
  `akapal-geap-ui/server.js`). Auth via ADC access token (`_access_token`).
- Engine identity from `AGENT_ENGINE_PROJECT` / `AGENT_ENGINE_LOCATION` /
  `AGENT_ENGINE_ID` env vars (previously a single `AGENT_ENGINE_RESOURCE` regex-parsed).
- `_strip_refs()` sanitizes the catalog at startup (strips external + internal
  `$ref`s, inlines `$defs.CatalogComponentCommon.weight`) so the agent's tool
  response passes Gemini function-response validation.
- `ChatRequest` Pydantic model → Swagger shows JSON body.

### a2ui-agent (`a2ui-agent/app/`)
- `agent.py` — `LlmAgent` with `google_search` (sub-agent wrapper, because
  custom function tools + built-in grounding can't share one request) +
  `get_a2ui_catalog` (FunctionTool fetching `<CATALOG_URL>/etcatalog`).
  Exposes `root_agent` (required by the Agent Engine `gemini_enterprise_app_name="app"`
  contract) + `agent` alias.
- `fast_api_app.py` — **load-bearing**: the Dockerfile CMD runs
  `uvicorn app.fast_api_app:app`; `get_fast_api_app(agents_dir=AGENT_DIR, gemini_enterprise_app_name="app")`
  serves the ADK agent over HTTP (`/api/stream_reasoning_engine`), which is what
  the Agent Engine platform proxies to. Without it the engine fails to start.
- `agents-cli-manifest.yaml` — `deployment_target: agent_runtime`, `is_a2a: false`,
  `agent_directory: "app"`.
- Deploy via `agents-cli deploy --deployment-target agent_runtime` (agents-cli
  builds the Docker image from the Dockerfile and uploads it).

### Known gotchas
- `MODEL_LOCATION=global` leaks from the Windows shell env — the deploy scripts
  `unset MODEL_LOCATION GOOGLE_CLOUD_LOCATION` before sourcing the env file;
  pass `GOOGLE_CLOUD_LOCATION=$REGION` explicitly.
- The catalog tool returns the full catalog JSON; the a2ui-server must serve it
  `$ref`-free (already does via `_strip_refs`).
- Ruff requires `__all__` sorted (`RUF022`) and specific string-concat formatting.
- `agents-cli deploy` needs a Dockerfile in the agent project root (it builds a
  container image for agent_runtime).
